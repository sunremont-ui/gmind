# 18 — Корневая навигация и дерево документов

## Назначение

Когда пользователь открывает `.md`, `.markdown` или `.xmind` из карты проекта,
он остаётся внутри контекста исходного каталога. Открытый документ не заменяет
проект как точку отсчёта: приложение сохраняет корневую карту, показывает путь
к файлу и позволяет вернуться назад, вперёд или сразу в корень.

Этот слой решает четыре связанные задачи:

1. навигация между документами без потери контекста проекта;
2. дерево документов текущего корня в Sidebar;
3. создание и удаление файлов из этого дерева;
4. управляемая ширина Sidebar для длинных имён и глубоких путей.

## Пользовательский сценарий

1. Пользователь импортирует каталог через модуль **Проекты**.
2. Каталог становится корневым workbook, а `Workbook.SourcePath` указывает на
   директорию.
3. Клик по ссылке `.md`, `.markdown` или `.xmind` открывает документ как
   отдельное workbook-представление.
4. Над холстом остаётся строка контекста: назад, вперёд, breadcrumb корня и
   кнопка показа активного файла в дереве.
5. В Sidebar остаётся дерево исходного каталога, даже если активен вложенный
   документ.
6. Кнопка **Карта корня** возвращает к схеме всего каталога.

`Alt+←` и `Alt+→` дублируют кнопки истории. История относится к документам и
листам оболочки, а не только к выбору узлов внутри одной карты.

## Модель корневого контекста

Фронтенд хранит `ProjectRootContext`:

```ts
interface ProjectRootContext {
  workbookId: string
  title: string
  path: string
  root: Topic
}
```

Корневой workbook определяется так:

- `source_path` существует;
- `source_path` указывает на каталог, а не на поддерживаемый документ;
- первый sheet содержит `root_topic` со схемой проекта.

Документ наследует предыдущий корневой контекст, только если его
`source_path` находится внутри этого каталога. Сравнение путей нормализует
слеши и регистр для Windows.

Ключевой файл: `frontend/src/utils/documentNavigation.ts`.

## История документов

`DocumentNavigationState` содержит массив снимков и текущий индекс. В каждый
снимок входят workbook, активный лист, выбранный узел и корневой контекст.

Инварианты истории:

- максимум 50 записей;
- повторное открытие того же workbook/sheet/topic обновляет текущую запись;
- новый переход после шага назад отбрасывает прежнюю ветку «вперёд»;
- перед переходом текущее состояние захватывается, чтобы восстановить лист и
  выделение;
- открытие документа из ссылки, Sidebar или breadcrumb идёт через один
  shell-уровень навигации.

Компонент строки контекста:
`frontend/src/components/DocumentContextBar/DocumentContextBar.tsx`.

## Дерево Sidebar

`ProjectTree` строится из сохранённой схемы корневого workbook и показывает
только документы `.md`, `.markdown`, `.xmind` и папки-предки этих документов.

Поведение дерева:

- все папки по умолчанию свёрнуты;
- отдельные кнопки сворачивают или разворачивают всё дерево;
- активный документ подсвечивается и прокручивается в видимую область;
- кнопка цели в строке контекста открывает Sidebar и показывает файл;
- корневая строка всегда доступна как **Карта корня**;
- остальные обычные workbook скрыты под секцией **Другие карты**, чтобы не
  смешивать их с файловой иерархией открытого проекта.

Ключевые файлы:

- `frontend/src/components/Sidebar/ProjectTree.tsx`;
- `frontend/src/components/Sidebar/Sidebar.tsx`;
- `frontend/src/App.tsx`.

## Создание файла

Создать Markdown-документ можно в корне или в любой видимой папке дерева.
Если расширение не указано, добавляется `.md`. Допустимы только `.md` и
`.markdown`; вложенный путь в поле имени запрещён.

Новый файл получает минимальное содержимое:

```md
# Имя файла
```

Создание эксклюзивное: существующий файл не перезаписывается и даёт `409`.
После успеха корневая карта пересканируется и сохраняется, нужная папка
раскрывается, а новый документ автоматически открывается.

## Удаление файла

Удалять можно документы `.md`, `.markdown` и `.xmind` внутри текущего корня.
UI всегда запрашивает подтверждение и предупреждает, что действие необратимо.

После удаления:

- корневой workbook пересканируется и сохраняется;
- временные workbook-представления удалённого файла удаляются из SQLite;
- если удалён активный документ, оболочка возвращается к карте корня;
- Sidebar получает обновлённое дерево.

Папки через этот API не удаляются.

## Project Files API

### POST `/api/v1/projects/files`

```json
{
  "root": "D:\\project",
  "workbook_id": "root-workbook-id",
  "directory": "D:\\project\\docs",
  "name": "plan.md"
}
```

Ответ `201` содержит абсолютный `path` и обновлённый `workbook`.

### DELETE `/api/v1/projects/files`

```json
{
  "root": "D:\\project",
  "workbook_id": "root-workbook-id",
  "path": "D:\\project\\docs\\plan.md"
}
```

Ответ `200` содержит `path`, обновлённый `workbook` и список
`deleted_workbook_ids`.

Backend: `backend/internal/api/project_files.go`.
Frontend client: `frontend/src/api/projects.ts`.

## Ограничения безопасности путей

Backend не доверяет путям из UI:

- корень и цель приводятся к абсолютному каноническому пути через
  `filepath.Abs` и `filepath.EvalSymlinks`;
- `workbook_id` должен принадлежать именно переданному корню;
- директория создания и удаляемый файл обязаны оставаться внутри корня;
- имя создаваемого файла не может содержать путь;
- создание использует `O_EXCL`, поэтому не перезаписывает данные;
- при ошибке пересканирования создание откатывается удалением нового файла, а
  удаление — восстановлением содержимого и режима исходного файла.

## Изменяемая ширина Sidebar

Правый край Sidebar является доступным `separator` и поддерживает мышь и
клавиатуру.

- диапазон: 220–560 px, но не больше 55% ширины окна;
- перетаскивание мышью меняет ширину без анимации;
- `←`/`→` меняют ширину шагом 16 px;
- двойной щелчок или `Home` возвращает 260 px;
- значение хранится в `localStorage` под ключом `gmind_sidebar_width`;
- свёрнутый режим остаётся фиксированным: 48 px.

## Тема и логотип

Тема карты по умолчанию — `midnight`. Выбор хранится в `localStorage` под
ключом `gmind_theme` и записывается в данные сессии как `lastTheme`.

При `midnight` приложение ставит на `<html>` `data-theme="dark"` и
`color-scheme: dark`, а Splash, Header и экран ошибки используют
`/lumen-logo-dark.svg`. При любой светлой теме возвращается
`/lumen-logo.svg`.

Важно: сейчас Midnight гарантированно затемняет холст карты и включает тёмный
вариант логотипа/CSS-схемы. Основная палитра Header и Sidebar по-прежнему
использует общие Lumen-токены; это не отдельная полностью тёмная shell-тема.

Функциональность покрыта тестами навигации, открытия ссылок, строки контекста,
дерева проекта, Sidebar, темы и backend project files API.

Контрольный прогон реализации:

- frontend: 40 файлов тестов, 428 тестов — успешно;
- production build — успешно;
- backend: `go test ./...` — успешно;
- browser-проверка: Midnight активен, тёмный логотип загружен, документ
  открывается из дерева и сохраняет корневой контекст.
