# Библиотека визуальных компонентов

Каталог заготовок для холста. Разделение с корпусами простое:

- **корпус** (`memoryPackages.ts`) отвечает «как выглядит этот вид памяти»;
- **компонент** (`componentLibrary.ts`) отвечает «что я сейчас кладу на холст».

Электронная аналогия та же: корпус — исполнение детали, компонент — позиция в
каталоге, которую берут и ставят на плату.

## Реестр — `frontend/src/renderer/componentLibrary.ts`

```ts
interface VisualComponent {
  id: string
  label: string
  category: 'memory' | 'structure' | 'task' | 'note'
  hint: string          // что это и когда брать
  spec: ComponentNodeSpec   // заготовка: узел (+ поддерево)
}
```

`ComponentNodeSpec` несёт только оформление и структуру: `title`, `body`,
`notes`, `memory_kind`, `shape`, `icon`, `border_color`, `node_style`,
`structure_class`, `children[]`. Никаких id и позиций — компонент это заготовка,
а не копия конкретного узла.

Встроенный набор:

| Категория | Компоненты |
|---|---|
| Память | по одному на слой karp + Решение, Понятие — оформление подтягивается из корпуса |
| Структуры | Радиальный хаб, Циферблат, Дерево решения, Линия времени, Матрица 2×2 |
| Задачи | Задача MASys, Чек-лист |
| Заметки | Заметка (голова+тело), Вопрос |

Структурные компоненты сразу задают раскладку: «Радиальный хаб» —
`radial-packed`, «Циферблат» — `radial-clock`, «Матрица» — `radial-even`.

## Расширяемость

Тот же приём, что у корпусов: встроенные компоненты в коде, пользовательские
внедряются извне, функции реестра остаются чистыми и синхронными.

- `setCustomComponents(list)` — вызывает `store/componentLibrary.ts`
  (Zustand + persist в localStorage);
- `allComponents()` / `componentsByCategory()` — с учётом переопределений;
  свой компонент с тем же `id` перекрывает встроенный, дублей не возникает;
- `componentFromTopic(topic, label, category)` — «сохранить узел как компонент»:
  переносит оформление, раскладку и всё поддерево;
- `validateComponent()` — проверка перед сохранением.

⚠️ **Гоча уникальности id.** Первая версия строила id из `Date.now()` — два
компонента, сохранённых в одну миллисекунду, получали один id, и один молча
перекрывал другой в реестре. Тест это поймал; теперь к метке времени
добавляется монотонный счётчик (`uniqueSuffix`).

⚠️ Стор импортируется в `App.tsx` намеренно — иначе rehydrate из localStorage не
запускается и палитра открывается без своих компонентов. То же, что с корпусами.

## Палитра — модуль «🧩 Компоненты» в Nav Rail

`components/ComponentLibrary/ComponentLibraryPanel.tsx`:

- вкладки категорий, сетка карточек с превью;
- **превью рисуется тем же `shapePath`**, что и настоящий узел, плюс штрихи вниз
  по числу детей — видно, что компонент положит не один узел;
- клик вставляет компонент **под выделенный узел**, а если ничего не выделено —
  под корень листа; после вставки карта перечитывается;
- «В библиотеку» сохраняет выделенный узел как свой компонент;
- у своих компонентов есть ✕ для удаления (у перекрытого встроенного это
  возвращает исходный).

Вставка идёт через `api.importTopicTree()` — тот же путь, что у импорта
Markdown: узел создаётся заголовком, а тело/заметка/оформление досылаются
вторым запросом (`createTopic` принимает только заголовок).

## Тесты

`componentLibrary.test.ts` держит инварианты каталога: уникальность id,
непустые категории (в палитре не будет пустых вкладок), **все формы заготовок
существуют в реестре форм**, **все виды памяти в заготовках имеют корпус** —
то есть каталог не может сослаться на несуществующее оформление. Плюс
переопределение своими компонентами, подсчёт узлов и перенос узла в компонент.
