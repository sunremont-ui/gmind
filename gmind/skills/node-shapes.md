# Формы узлов

Единый реестр форм: `frontend/src/renderer/shapes.ts` (+ `shapes.test.ts`).
Из него берут данные **все** потребители — рендер узла, layout и панель
свойств, поэтому превью в UI не может разойтись с настоящим узлом.

## Базовый набор

| id | Название | Особенность |
|---|---|---|
| `rounded` | Скруглённый | дефолт; радиус из темы |
| `rectangle` | Прямоугольник | без дуг |
| `pill` | Капсула | радиус = половина меньшей стороны |
| `ellipse` | Эллипс | сильный рост бокса под текст |
| `diamond` | Ромб | сильный рост (углы срезаны) |
| `triangle` | Треугольник | самый сильный рост: текст живёт в нижней половине |
| `hexagon` | Шестиугольник | боковые срезы 18% ширины |
| `parallelogram` | Параллелограмм | скос 16% ширины |
| `note` | Лист | загнутый угол ≤16px |
| `cloud` | Облако | путь на кривых Безье |

## API

```ts
shapePath(shape, w, h, r): string   // SVG-путь контура в локальных координатах
shapeGrow(shape): { w, h }          // во сколько раз раздуть бокс под текст
shapeTextInset(shape, w, h): Rect   // прямоугольник под голову+тело внутри формы
shapeDef(shape): ShapeDef           // определение; неизвестный id → rounded
NODE_SHAPES: ShapeDef[]             // список для UI
```

Неизвестный `shape` (старый файл, чужой импорт, опечатка агента) молча
откатывается к `rounded` — карта не должна ломаться из-за одного поля.

## Как это связано

- **`components/MindMap/TopicNode.tsx`** рисует **один** `<path>` на любую
  форму. Раньше ромб был повёрнутым на 45° `<rect>` (текст оставался
  горизонтальным, но габариты врали), облако — inline-путём, остальное —
  `<rect rx ry>`. Теперь ветвление одно: `shapeOutline`.
- Голова и тело живут в `foreignObject` внутри `shapeTextInset(...)` плюс
  внутренние отступы узла (`nodePad`). У ромба это центральные ~56%×60%.
- **`renderer/layout.ts`** после `measureNodeSize` умножает бокс на
  `shapeGrow(shape)`, где `shape` — **итоговая** форма из
  `topicShape(topic)` (`renderer/memoryPackages.ts`): у узла без явной
  `shape` её задаёт корпус вида памяти. Мерить прямоугольник и рисовать ромб
  нельзя — врезка формы срежет текст. Явные `node_width` / `node_height`
  пользователя не трогаются — иначе заданный размер «уезжал» бы при смене формы.
- **`components/PropertiesPanel/ShapePicker.tsx`** — сетка миниатюр (3 колонки)
  и `ShapePreview`; обе рисуются тем же `shapePath`.

## Добавить форму

1. Дописать запись в `NODE_SHAPES`: `id`, `label`, `path`, `grow`, при
   необходимости `textInset`.
2. Всё остальное подхватится само: рендер, layout, пикер, экспорт в `.md`
   (`shape` едет в `<!-- gmind: … -->`).
3. Тесты в `shapes.test.ts` параметризованы по `NODE_SHAPES` — новая форма
   автоматически проверяется на замкнутость пути, отсутствие `NaN` на
   вырожденных размерах (`0×0`, `400×4`), `grow ≥ 1` и врезку внутри бокса.

## Гочи

- Путь строится в локальных координатах узла: `(0,0)` — левый верхний угол,
  `(w,h)` — правый нижний. Позиционирование делает `<g transform>` в TopicNode.
- Радиус скругления зажимается половиной стороны — иначе контур выворачивается
  на маленьких узлах.
- В режиме правки контур считается по размеру редактора (`editWidth`/
  `editHeight`), а текстовая врезка — по layout-размеру: редактор растёт под
  набор, а якоря рёбер садятся на грани расширенного узла.
